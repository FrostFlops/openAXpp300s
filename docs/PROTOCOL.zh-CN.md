# openaxpp300s 协议参考

本文说明 openaxpp300s 如何通过 USB 串口与 AX PP300S 台式电源通信。读者对象是想要实现或审查客户端的人，以及想知道电源收到一帧数据后会做什么的人。

## 约定与证据等级

每一条协议结论都标注了它的来源。

| 标签 | 含义 |
|---|---|
| FIRMWARE | 来自电源固件 V1.4.4 的反汇编。给出代码地址（`0x0800xxxx`，flash）或变量地址（`0x2000xxxx`，RAM）。若反汇编还在模拟器中运行过，正文会注明。 |
| MEASURED | 2026-11-07 在真实电源上分三次实测：AX PP300S 固件 V1.4.4，Windows 11，CH340 USB 转串口芯片，输入 19.8 V（第二次和第三次由 Type-C 电源输入口上的 65 W USB-PD 充电器供电）。参考仪器：Fluke 289，作电压表用（输入阻抗 10 MOhm），与电子负载串联时作电流表用（A 端子）。 |
| VENDOR | 来自厂商串口协议 PDF、厂商用户手册 V1.1、厂商上位机 V1.2，或随固件 V1.4.4 提供的更新记录。 |
| INFERRED | 由代码、命名或类比推断，未被证实。应视为假设。 |

线上所有多字节整数除特别说明外均为小端。十六进制转储以空格分隔字节。单位采用 SI：伏特、安培、瓦特、秒、摄氏度。需要时会给出设置单位（10 mV、10 mA）。串口名一律写作 `COMx`。

### 硬件验证状态

2026-11-07 在真实电源上分三次验证通过（固件 V1.4.4，Windows 11，CH340）。

第一次：

- 端口发现、status、selftest；
- 设置 VSET、ISET、OVP、OCP、DELAY、REV、OPP 和 OTP（每帧都收到 ACK）；
- 输出开和关；
- 0.5 V 至 15 V 的 VSET 精度，对照 Fluke 289（第 12.2 节）；
- 在输出开启时同时降低 VSET 和 OVP（未触发保护）；
- DELAY、REV、watch、sequence、raw 查询以及本工具的拒绝逻辑；
- 两次 OVP 触发（第 7 节）。

第二次（使用本工具审查修复后的最新代码；输入来自 65 W USB-PD 充电器）：

- 0.5 V 至 30 V 的 VSET 精度，包括升压到 20、24 和 30 V（第 12.2 节）；
- MCP 服务器对真实电源的使用（ports、status、selftest、set、输出开关、watch、log、sequence，以及工具的拒绝逻辑）；
- 带载 CV，以及电流校准之前 0.1 A 至 1 A 的限流（CC），用电子负载测试，以 Fluke 289 作电流表对照（第 12.3 和 12.4 节）；
- 带载时 CV 和 CC 下的 CC 标志（字节 11，第 5.3 节），以及负载处于恒阻模式时它在 CC 与 CV 之间的交替（第 12.6 节）；
- 1 A 电流流过时同时降低 ISET 和 OCP（先发 ISET，未触发保护）；
- CV 优先与 CC 优先（寄存器 0x10）：它对开机瞬间电流的影响（第 12.5 节）；
- 显示颜色（第 6.4 节）；
- 中文界面：参数列表（生效、实时修改、选择；第 6.3 节），Digital VSET 和 DELAY 在其上被忽略（第 6.1 节），关断电流和关断时间（第 8 节），以及关断是无声的；
- 用面板输出键开启输出、没有任何主机帧，由 Fluke 289 看到（第 5.4 节）。

第三次（用户在面板上以 Fluke 289 为基准校准了电源的电流之后；输入相同）：

- 0.05 A 至 5 A 的限流（CC），对照 Fluke 289，每个点都在厂商规格之内（第 12.4 节）；CC 已验证到 5 A 和约 17.5 W，没有触发任何保护。

尚未在硬件上验证：

- OCP、OPP、OTP 触发（只在第一次见过两次 OVP 触发；第二次和第三次没有任何保护触发）；
- 设备设置菜单的影响（第 10.2 节）；
- 5 A 以上的电流和约 20 W 以上的功率；
- DC5525 输入接口；
- 约 3 V 以外输出电压下的 CC 精度（所有 CC 点都在该电压下取得）；
- EEPROM 写入本身：有代码证据表明每一帧（包括状态查询）都会置位保存标志（第 9 节），但没有在硬件上观察到写入。

本文中涉及这些方面的内容只有 FIRMWARE 或 VENDOR 证据。

## 1. 概述

```
PC (openaxpp300s)  <--- USB, CH340 串口, 115200 8N1 --->  AX PP300S  (第二个 Type-C 口, 即串口)
```

| 部分 | 作用 |
|---|---|
| AX PP300S | 升降压台式电源，0 至 30 V，0 至 10 A，300 W（VENDOR）。其微控制器负责调节、保护、显示和串口通信。 |
| CH340 芯片 | USB 转 UART 转换器。MEASURED：枚举为 USB-SERIAL CH340，VID:PID 1A86:7523。 |
| openaxpp300s | PC 端客户端（命令行、库、MCP 服务器）。 |

链路参数：

| 项目 | 值 | 证据 |
|---|---|---|
| 接口 | 第二个 Type-C 口，手册中称为串口的 Type-C 口 | VENDOR |
| 波特率 | 115200 | FIRMWARE：初始化函数 `0x0800E29C`，在 `0x0800E160` 以 0x1C200 调用；VENDOR |
| 格式 | 8 数据位，无校验，1 停止位，无流控 | FIRMWARE：初始化结构 `0x0800E2FC` 至 `0x0800E310` |
| DTR、RTS | 未使用。以任一电平打开端口都不会使电源复位。 | MEASURED |
| 设备 UART | USART1（PA9 TX，PA10 RX），是唯一有效的 UART。 | FIRMWARE |
| 供电 | 这是数据口，不是供电输入。手册称单独插入该口不会使电源启动，也不会损坏电源。 | VENDOR |

电源是纯应答设备。它不发开机信息，不发周期性遥测，也不会主动通知保护触发、关断或面板改动（FIRMWARE：发送函数 `0x0800E33C` 只有两处调用，一处是 `0x08000ED4` 的 ACK，一处是 `0x08000FAA` 的状态应答循环）。主机必须轮询。

电源无法回报自己的设置、当前界面、光标或报警。主机能读到的只有实测输出、输入电压、温度和两个标志位（第 5 节）。主机若想知道某个设定值，必须自己记住发送过什么。

## 2. 帧格式

主机到电源，固定 6 字节：

```
A5  ID  dataLo  dataHi  chk  5A
```

| 偏移 | 字段 | 含义 |
|---|---|---|
| 0 | `A5` | 帧头。 |
| 1 | ID | 寄存器 ID（第 6 节）。 |
| 2 | dataLo | 数据字，低字节。 |
| 3 | dataHi | 数据字，高字节。 |
| 4 | chk | `(ID + dataLo + dataHi) mod 256`。 |
| 5 | `5A` | 帧尾。 |

VENDOR 与 FIRMWARE：校验在 `0x080008E6` 至 `0x0800090A` 计算。数据字为 `dataLo + 256 * dataHi`；各寄存器按第 6 节的方式解释它。

示例，VENDOR：`A5 00 E8 03 EB 5A` 把 VSET 设为 10.00 V（0x03E8 = 1000 个 10 mV）。`A5 08 01 00 09 5A` 打开输出。`A5 0F 05 01 15 5A` 把列表 0 关断时间的分钟字段设为 5。查询帧是 `A5 FF 00 00 FF 5A`。

电源到主机，有两种应答：

| 应答 | 字节 | 时机 |
|---|---|---|
| ACK | `01` | 除 ID 0xFF 外，每个有效帧之后（第 4 节）。 |
| 状态应答 | 15 字节，`A5 ... 5A` | ID 0xFF 之后（第 5 节）。 |

## 3. 字节解析器

FIRMWARE（`0x08000878` 至 `0x0800090A`，由 USART1 接收中断 `0x0800CEE4` 调用；还在模拟器中针对全部 256 个 ID、正确帧与错误帧运行过）：

- 解析器是字节状态机，有两个状态：寻找帧头和收集。
- 寻找帧头：等于 `A5` 的字节开始一帧，其他字节被丢弃。
- 收集：接下来的 5 个字节不经检查直接存入，所以值为 `A5` 的数据字节没有问题。第 5 个字节之后解析器总是回到寻找帧头状态。
- 第 5 个字节之后，只有当 `ID + dataLo + dataHi` 等于校验字节且最后一个字节为 `5A` 时才接受该帧；否则这 5 个字节被静默丢弃。
- 解析器从不寻找帧尾，也不会重新扫描已消耗的字节。

后果：

| 情形 | 结果 | 证据 |
|---|---|---|
| 帧前有不含 `A5` 的杂乱字节 | 无害。 | FIRMWARE |
| 真帧前有一个多余的 `A5` | 多余的 `A5` 加后面 5 个字节组成一个坏帧。真帧被吞掉：它的 `A5` 与后 4 个字节被消耗，它的 `5A` 在寻找帧头时被丢弃，没有 ACK。 | FIRMWARE；MEASURED（有效查询前加 `00 11 5A A5`，查询被吞掉） |
| 一个字节因 UART 错误丢失 | 与多余 `A5` 相同：下一帧被吞掉。 | FIRMWARE |
| 校验或帧尾错误 | 不存储，不应答。 | FIRMWARE；MEASURED（校验错误，无应答） |
| 一帧分几次写入 | 只要整帧在下述超时内到达就没有问题。 | FIRMWARE |

字节间超时，FIRMWARE（`0x0800AD74`，`0x0800AD9A` 至 `0x0800ADC0`）：定时器 TIM2 以 10 kHz 运行。处于收集状态时它递增一个计数器；计数超过 100 时强制解析器回到寻找帧头状态。计数器只在接受 `A5` 时清零，而不是每个字节清零。因此整帧必须在其 `A5` 之后约 10 ms 内到齐。115200 波特下 6 字节帧耗时 0.52 ms。不完整的帧在其 `A5` 之后约 10.1 ms 被放弃，没有 ACK。72 MHz 的定时器时钟由时钟配置推断（INFERRED）。MEASURED：一帧拆成 3 + 3 字节、两半间隔 20 ms，没有得到任何应答。

UART 错误，FIRMWARE（`0x0800CEE6` 至 `0x0800CF2A`）：带有奇偶、溢出或帧错误的字节在到达解析器之前被读出并丢弃。噪声标志不检查。

帧与帧之间不要求最小间隔。背靠背的有效帧都会被处理并应答（FIRMWARE）。

主机的重新同步规则（由上述超时推断，INFERRED）：应答缺失后，至少空闲 11 ms，使解析器确定处于寻找帧头状态（半收的帧已超时），然后重发。

## 4. 应答

FIRMWARE：ACK 是单个字节 `01`，在 `0x08000ED4` 由分发器的公共尾部（`0x08000EC8` 至 `0x08000ED4`）发出，位于接收中断内。该尾部的逻辑是：若 ID 不是 `0xFF`，就发送 `01`。

| 规则 | 证据 |
|---|---|
| 校验和帧尾有效的每一帧都会被应答，ID 0xFF 除外。 | FIRMWARE；MEASURED；VENDOR（PDF 称每次设置都回传 `01`） |
| 这包括全部未使用的 ID（共 204 个）、超出任何范围的值，以及高字节不是 0、1、2 的关断时间帧（不存储，但仍应答）。 | FIRMWARE（默认分支 `0x080009D4`，直通处 `0x08000C2E`，其他列表同理） |
| 没有 NAK，也没有错误码。未收到 ACK 的帧要么无效，要么被吞掉。 | FIRMWARE |
| ID 0xFF 只得到 15 字节应答，没有 ACK。 | FIRMWARE（`0x08000ECE`） |

有效帧的事件顺序，FIRMWARE：检查校验和帧尾；置位标志 `0x20000216`；分支代码把值存入对应的 RAM 变量；发送 ACK。所以 ACK 的意思是"帧已被接受并存入 RAM"。它不表示该值已生效、已保存或合理。后续影响：

| 影响 | 帧之后的延迟 |
|---|---|
| 调节和 OVP/OCP 检查使用新值 | 约 1 ms（TIM2 的 1 kHz 时隙） |
| 输出开关、DELAY、REV | 最多 50 ms（TIM3 节拍），外加 DELAY |
| 光标所在字段写 EEPROM（第 9 节） | 约 20 ms，在主循环中 |
| 颜色保存与重绘 | 210 ms 或更长 |

MEASURED：ACK 在帧写出约 12 至 14 ms 后到达（CH340 的 USB 延迟；固件在帧尾后约 0.2 ms 内发出）。若 ACK 应发出时线上正有应答字节，ACK 会等发送器结束（FIRMWARE：发送函数先等待 TC 标志）。

## 5. 状态应答

### 5.1 请求

帧 `A5 FF lo hi chk 5A`。数据字节被忽略，但必须使校验有效；本工具发送数据 0。FIRMWARE：接收中断只置一个标志（`0x20000207`，在 `0x08000EC0`）；应答稍后由 50 ms 定时中断发出（TIM3，`0x0800C1A8`；周期 499，预分频 7199，经 `0x0800CA4C` 设置）。

### 5.2 布局

15 字节。偏移从 0 开始。FIRMWARE（构造函数 `0x08000EE8`，打包函数 `0x08000F7C`）与 VENDOR（PDF，布局相同）。

| 偏移 | 大小 | 字段 | 单位 | 说明 | 证据 |
|---|---|---|---|---|---|
| 0 | 1 | 帧头 | | `A5` | FIRMWARE |
| 1 | 2 | Vout | 1 mV | 输出电压。实际为无符号。内部值小于 9（mV 刻度）时读作 0（`0x0800C646` 至 `0x0800C65C`）。 | FIRMWARE |
| 3 | 2 | Iout | 1 mA | 输出电流。 | FIRMWARE |
| 5 | 2 | Pout | 10 mW | `Vout_mV * Iout_mA / 1000`（单位 mW）再除以 10（`0x0800C666`，`0x0800C954`）。 | FIRMWARE |
| 7 | 2 | Vin | 10 mV | 正在使用的输入口的电压。每秒由一个 ADC 通道乘以校准系数算出一次（`0x0800B0B2` 至 `0x0800B15C`）。代码本身不确定单位；厂商 PDF 给出 0.01 V，与真实电源上的读数（0x07BD = 19.81 V）一致。 | FIRMWARE，VENDOR，MEASURED |
| 9 | 2 | 温度 | 0.1 C | 主机按有符号 16 位解释（固件在打包前对六个值都做了符号扩展）。由显示循环写入（`0x08008C4E`）。单位与厂商 PDF 一致，也与风扇阈值 50.0 C 和 45.0 C 以及 OTP 比较相符（由代码推断，INFERRED）。 | FIRMWARE，VENDOR |
| 11 | 1 | CC 标志 | | 只有 0 或 1（第 5.3 节）。 | FIRMWARE |
| 12 | 1 | 输出标志 | | 只有 0 或 1（第 5.4 节）。 | FIRMWARE |
| 13 | 1 | 校验 | | 字节 1 至 12 之和 mod 256。 | FIRMWARE（`0x08000F48`）；VENDOR |
| 14 | 1 | 帧尾 | | `5A` | FIRMWARE |

示例，VENDOR：`A5 88 13 00 00 00 00 B4 07 25 01 00 01 7D 5A` 表示 Vout 5.000 V（0x1388）、Iout 0 A、Pout 0 W、Vin 19.72 V、29.3 C、CV、输出开启；校验为 0x7D。

应答中没有 OVP、OCP、OPP、OTP、SCP 标志字段，没有设定值，也没有界面信息（FIRMWARE：应答代码不读取触发标志 `0x20000120` 至 `0x20000124`，也不读取关断标志 `0x200001A0` 和 `0x200001A1`）。

### 5.3 字节 11，CC 标志

FIRMWARE：唯一的写入点是 `0x0800AF72` 和 `0x0800AF7A`，位于 TIM2 的 1 kHz 时隙。代码对某个 ADC 通道取 2 次采样的平均（`0x08008B0C`），平均值小于 3600 计数时存 1，否则存 0。固件自己在调节中把它用作硬件 CC 指示（`0x0800B38C`）。无论输出状态如何它都会计算。

对主机的含义：

| 条件 | 字节 11 | 证据 |
|---|---|---|
| 输出开启，恒压 | 0 | MEASURED（软启动之后，0.5 A 负载下的 CV 也是如此） |
| 输出开启，恒流 | 1 | FIRMWARE；带载 MEASURED（电子负载 CV 模式 3.0 V，第二次 ISET 0.1 至 1.0 A，第三次 0.05 至 5 A：每一步工具都报告 CC） |
| 输出开启后的头约 1.1 s（软启动：输出停在约 0.011 V，之后上升） | 1 | MEASURED |
| 输出关闭 | 无意义。读到 1（见过一次 0）。无输出时该检测节点读数偏低；原因为推断（INFERRED）。 | MEASURED |

只有字节 12 为 1 时显示屏才显示 `STATE: CV` 或 `STATE: CC`，否则显示 `STATE: CLOSE`（FIRMWARE `0x080019E0` 至 `0x08001A46`）。主机规则：字节 12 为 0 时忽略字节 11；输出开启后头 1.5 s 内的字节 11 = 1 不要当作真正的限流。本工具在字节 12 为 0 时报告 `mode` 为 OFF，否则按字节 11 报告 CC/CV；同时也给出原始的 `cc_flag`。

### 5.4 字节 12，有效输出状态

FIRMWARE：字节 12 是 `0x20000102`。它不是命令状态 `0x20000101`（寄存器 0x08 写的那个）。以下任一情况成立时它为 0：

- DELAY 尚未到时；
- REV 的关闭半周期；
- 中文界面按电流或按时间关断之后（MEASURED，第 8 节）；
- 任何保护触发之后；
- 面板 OFF 之后；
- 进入设置菜单之后（`0x08003AFE` 至 `0x08003B06`）。

MEASURED：DELAY 和 REV 为 0 时，ON 之后字节 12 立即变 1，OFF 之后立即变 0。DELAY 3 s 时输出在 ON 命令后 4.39 s 才开启（3 s 加软启动）。REV 2 s 时输出约 2 s 后开启，之后每 2 s 翻转一次；9 s 内输出开启了 3.6 s，每次软启动期间 CC 标志为高。

字节 12 = 1 并不保证输出真的有电。FIRMWARE（`0x0800B26A` 至 `0x0800B2F2`）：1 kHz 时隙对输出使能脚（PC6）还有两个额外条件，含义为推断（INFERRED）：

- 在中文界面，光标位于列表选择框（光标 6）且旋钮处于数值编辑模式时，PC6 被保持关闭；
- 只有当另一个 ADC 通道（2 次采样平均乘以 1.692）低于 1600.0 时 PC6 才被驱动为开。

这两种情况下，应答都显示开启，而输出实际上是关闭的。第二个条件在正常使用中是否会起作用尚未解决（第 15 节）。

主机只能通过字节 12 在没有主机命令的情况下降为 0 来看到触发。它无法与面板 OFF、中文界面关断、REV 的关闭相位或进入设置菜单区分开。FIRMWARE：每次触发都会清除 `0x20000101` 和 `0x20000102`，并把 PC6 拉低。

MEASURED：在工具没有发送任何 ON 帧的情况下，输出开启了三次（Fluke 289 的记录中可见）；是用户按了面板上的输出键。此时应答的字节 12 = 1、与远程 ON 之后完全一样，这一点来自代码而不是读数：只有字节 12 为 1 时 PC6 才会被驱动为开（FIRMWARE，见上文）。所以主机无法分辨是谁开启了输出，生效的设置也可能与工具上次发送的不同。当输出开启而工具并未开启它时，工具的 `status` 会给出提示。

### 5.5 刷新率与数据陈旧

| 数值 | 刷新 | 证据 |
|---|---|---|
| Vout、Iout、Pout | 每隔一个 50 ms 节拍刷新，即每 100 ms 一次（奇偶判断 `0x0800C1C4`）。 | FIRMWARE |
| Vin | 每秒一次。 | FIRMWARE（`0x0800B0B2`） |
| 温度 | 由显示循环刷新；速率为推断。 | FIRMWARE，INFERRED |
| 字节 11 | 每 1 ms。 | FIRMWARE |
| 字节 12 | 每个 50 ms 节拍（TIM3 输出逻辑）。 | FIRMWARE |

设备的设置菜单打开时，Vout、Iout、Pout 不再刷新（`0x0800C1CE` 跳过更新），温度也不刷新。此时应答携带的是冻结的值。FIRMWARE。

数值在 TIM3 节拍时采样，而不是请求到达时。同一个 50 ms 节拍内的多次查询只产生一次应答（FIRMWARE；MEASURED：一次写入两个查询只得到一个应答）。在应答发送过程中置位的查询标志会在发送后被清除，不会被应答（FIRMWARE，依据代码顺序）。

延迟，MEASURED：状态应答在查询之后 15 至 55 ms 到达（下一个 50 ms 节拍加 USB 延迟），中位数约 48 ms。FIRMWARE 估计：0 至 50 ms，加发送 15 字节约 1.3 ms；面板上按住按键会拖慢节拍（INFERRED）。

### 5.6 交错风险

FIRMWARE：15 字节应答在 TIM3 中断内（抢占级 2，循环在 `0x08000FA6` 至 `0x08000FB6`）逐字节忙等发送。USART1 接收中断级别为 0，可以抢占它。在应答发送的约 1.3 ms 内收齐的设置帧会运行其中断，等待发送器空闲，并把它的 `01` 写在应答的两个字节之间。主机会看到被破坏的应答。

规则：等待查询应答时，绝不能有设置帧在途；应答未完整收到前不要发送任何帧。校验每个应答（帧头、帧尾、校验和），并丢弃输入直到下一个 `A5` 来重新同步。

## 6. 寄存器表

FIRMWARE（分发器 `0x0800090C`，表 `0x08000922` 和 `0x080009A6`；全部 256 个 ID 都在模拟器中运行过）与 VENDOR（PDF，厂商上位机 V1.2）。数据是 16 位字。代码存储它时没有任何范围检查：每个 ID 都接受 0 至 65535。下面的范围是面板限值（旋钮例程 `0x08008092` 至 `0x0800810E`、`0x08008302` 至 `0x0800836C` 和 `0x0800848C` 至 `0x08008920`）以及厂商 PDF 的范围。固件在串口路径上并不强制这些范围。主机工具必须自己强制。

界面列："Digital" = 数字界面和曲线界面，"Chinese" = 中文界面（V1.4.4 中菜单项名为 "Chinese"，FIRMWARE 字符串；手册 V1.1 仍称其为 Digital2，更新记录说明它在固件 1.4.2 中改名，VENDOR），"any" = 所有界面。厂商 PDF 的分组方式相同。

### 6.2 危险的值

FIRMWARE：

- 超出范围的 VSET 和 ISET 会不加限制地送到 PWM（双精度结果用 16 位扩展截断，`0x0800B638`）；硬件上的效果是推断（INFERRED），且未解决（第 15 节）。
- OVP、OCP、列表 OVP、列表 OCP 或 OTP 为 0 是永久触发；OTP 为 1 至 5 会在 10 至 50 C 时触发（第 7 节）。
- 把 OVP、OCP、OPP 或 OTP 设得很高等于取消该保护（OVP 超过约 3050，OCP 超过 1200，OPP 最高 2560 W，OTP 最高 2550 C）。
- 0x09 的数据为 5 或更大是越界列表索引，会被不加检查地保存到 EEPROM 0x3B，并在开机时重新加载（`0x0800E000`）。
- 0x08 ON 在触发之后重新开启输出（第 7 节）。
- 0xFF 和任何其他帧都会造成 EEPROM 磨损（第 9 节）。

不存在校准、擦除、复位、flash 或 bootloader ID（FIRMWARE：镜像中没有 `0x05FA0004` 复位请求常数，也没有 flash 解锁密钥）。

- 写入列表 0（VSET 2.0 V，OVP 2.5 V）后再选中它，先写数值，最后发列表选择 0x09。ON 之后输出稳定在 1.9975 V（回读平均值）：驱动输出的是列表值，而不是 Digital VSET。
- 输出开启时把列表 0 改为 VSET 2.4 V（OVP 2.9 V），输出立即跟随（2.401 V）。
- 写入列表 1（VSET 1.2 V，OVP 1.7 V）。工具在发送任何内容之前就拒绝选择它，因为它的 OVP 1.7 V 低于当前 2.4 V 的输出，会触发。固件本身没有这样的检查（0x09 不加检查地存储）。把列表 1 的 OVP 提高到 3.0 V 之后选择成功，输出变为 1.2 V；没有触发。

## 7. 保护

FIRMWARE。触发标志：OVP `0x20000120`，OCP `0x20000121`，SCP `0x20000122`，OTP `0x20000123`，OPP `0x20000124`。

| 保护 | 触发条件 | 位置 | 输出关闭时是否检查 |
|---|---|---|---|
| OVP | OVP 设定值小于或等于实测电压（均为 10 mV 单位）。无消抖。面板电压校正模式开启时不生效。 | TIM2 1 kHz 时隙，`0x0800B040` 至 `0x0800B068`（中文界面：`0x0800AFB4` 至 `0x0800AFEC`） | 是 |
| OCP | OCP 设定值小于或等于实测电流（限幅在 12.00 A），连续 100 个 1 ms 采样（约 100 ms）。面板电流校正模式开启时不生效。 | TIM2 1 kHz 时隙，`0x0800B06A` 至 `0x0800B0B0` | 是 |
| OPP | `floor(Pout 的 mW 值 / 1000)` 大于以 W 为单位的 OPP 限值。 | 主循环，`0x08001368`（Digital）和 `0x08002200`（Chinese） | 是（此时功率为 0） |
| OTP | 温度（0.1 C）大于或等于 `n * 100`。 | 主循环，`0x0800195E` 和 `0x08002224` | 是 |
| SCP | 从不触发：该标志在 V1.4.4 中没有任何置位代码。 | `0x20000122` | 不适用 |

触发时，FIRMWARE：输出使能脚被拉低，`0x20000101` 和 `0x20000102` 都被清零，并置位触发标志。显示屏显示 `Warning: OVP`（或 OCP、OTP、OPP），并响起报警音。

- 因为 OVP 和 OCP 在输出关闭时也与端子实测值比较，输出端上的电池或已充电的电容，或者低于当前存在电压的 OVP，都会使处于关闭状态的电源触发。OVP 为 0 会在 1 ms 内触发并不断重新触发；OCP 为 0 约 100 ms 后触发。
- OPP 和 OTP 只在界面的主循环中检查；设置菜单打开时不检查。
- 报警和标志只有在面板按键被按下时才清除（按键扫描由 TIM3 运行；清除在 `0x08009328` 至 `0x0800933C`，同时停止报警音）。没有串口寄存器可以清除触发或读回触发。
- 触发之后远程 ON（寄存器 0x08）会重新开启输出；该路径上没有任何代码读取触发标志。MEASURED：OVP 触发之后，随后的远程 ON 有效。如果故障仍在，会再次触发。
- 触发对主机的唯一可见迹象是字节 12 降为 0（第 5.4 节）。

MEASURED：两次 OVP 触发。（1）OVP 2.00 V、VSET 3.00 V（有意为之）：电压上升时输出关闭，字节 12 变 0，字节 11 读 1；报警一直响到按下面板按键。（2）VSET 3.00 V、OVP 3.00 V（意外）：在从 2 V 的阶跃时触发，因为阶跃时电压会超过设定值。这就是本工具让 OVP 至少比 VSET 高 `max(0.2 V, 1.5 %)` 的原因（第 13 节）。尚未 MEASURED：OCP、OPP、OTP 触发。第二次和第三次没有任何保护触发。中文界面的关断不是保护：它们是无声的（第 8 节）。

主机设置的 OVP 和 OCP 值只能通过第 6.6 节的光标规则被保存；OPP 和 OTP 只有在之后退出面板设置菜单时才被保存。

## 8. 关断电流与关断时间（中文界面）

FIRMWARE。两者都在 TIM3 中断中每秒运行一次，且只在界面为中文界面时运行。它们使用被选中的列表。

关断电流（`0x0800C7A0` 至 `0x0800C808`）：字节 12 为 1 时，若 Iout 低于 `值 * 10 mA`，计数器递增；否则复位。输出关闭时也复位。计数器大于 5（约连续 6 秒；手册称 5 秒）时输出被关断：PC6 拉低，字节 12 和 `0x20000101` 清零，置位标志 `0x200001A0`。值为 0 时禁用该功能。该标志不会通过串口报告。MEASURED：关断电流 0.1 A、实际电流约 0 A 时，输出在约 5.5 至 6 s 后自行关闭（固件计数器必须超过 5）。

关断时间（`0x0800C80A` 至 `0x0800C858`）：若 `h * 3600 + m * 60 + s` 小于或等于累计开机时间 `0x20000128`，输出以同样方式被关断（标志 `0x200001A1`）。无论输出状态如何，该检查都会运行。

- 开机时间在字节 12 为 1 时按秒计数，在任何界面都计数（`0x0800C70E`）。它在 OFF 与 ON 之间累计。只在关断时间触发后输出重新开启时复位（`0x0800B2AC`），或由面板统计清除复位。正常的 OFF/ON 不会复位它。MEASURED：关断时间比较的是自上电以来累计的开机时间，而不是自上一次 ON 以来的时间。
- 默认值是 99:60:60（约 100 小时）：等效于关闭。总时间 0:0:0 会在每次 ON 后约 1 秒内切断输出；它并不禁用计时器。
- 把总时间设得小于累计开机时间，会使下一次 ON 在约 1 秒内被切断（由代码推断，INFERRED）。MEASURED：电源上电后累计开机时间已超过 10 s，此时把总时间设为 0:00:10，第一次 ON 立即被切断。
- MEASURED：关断时间触发之后计数器重新开始。第二次 ON 保持了约 9 至 10 s，然后被切断。
- 时、分、秒是相互独立的字段，所以完整的时间需要 3 帧（`A5 0F 05 01 15 5A` 把分钟字段设为 5；VENDOR 示例）。
- 保存：若 n 被选中且光标在关断时间上，则恰好写入一个字节，由数字子光标选择（时、分或秒；EEPROM 0x46、0x47、0x48 加 13n；`0x08007406` 至 `0x0800748E`）。

MEASURED：两种关断都是无声的。电源没有蜂鸣（用户确认），这与保护触发不同（第 7 节）。主机唯一的迹象是字节 12 降为 0（第 5.4 节）；每次关断之后，工具的 `status` 都读到了这一点。当 `on` 等待结束时输出标志仍为关，工具的提示会把中文界面的关断（无声；自上电以来的开机时间）列为可能原因。

## 9. EEPROM 写入与磨损

FIRMWARE，注明处另有 MEASURED。

电源把设置保存在外部 I2C EEPROM 中（器件地址 `0xA0 | ((addr >> 8) << 1)`；由这种寻址方式推断为 24Cxx 类器件，INFERRED）。内部 flash 从不被编程（镜像中没有任何 flash 解锁密钥；反汇编的手工检查）。EEPROM 字节写入函数（`0x08000384`）依次发送起始、器件字节、地址、数据和停止，然后等待 10 ms。写入前不读取也不比较。地址固定。没有磨损均衡，也没有环形缓冲。

每一帧都会保存光标字段。解析器在 `0x0800090C` 置位的标志，与旋钮转动时编码器置位的是同一个标志（`0x20000216`；另一方向是 `0x20000217`）。界面循环每一轮都检查它（`0x08001330`，由 `0x0800274C` 和 `0x08007744` 调用；中文界面：`0x080066AC`）。它被置位时，循环写入光标（`0x2000011C`）所在的字段并清除标志。每个有效帧都会这样，包括状态查询（ID 0xFF）和未使用的 ID。

状态查询会置位该标志的代码证据（FIRMWARE，手工检查）：校验和帧尾通过之后，`0x0800090C` 至 `0x08000910` 的指令把 1 存入 `0x20000216`。这发生在 `0x08000912` 读取 ID 并分发之前，所以 0xFF 查询同样会置位该标志。`0x08000EC0` 处的查询分支只置位应答待发标志 `0x20000207`。主循环的保存（`0x08001DEE` 调用 `0x08001F86`）只要标志被置位，就写入光标所在的字段。EEPROM 写入本身没有在硬件上观察到；那需要在 EEPROM 的 I2C 线上接探头（第 15 节）。

| 界面与光标 | 每帧写入 |
|---|---|
| 数字或曲线界面，光标 0 至 5 | 2 字节：VSET（0x04/0x05）、ISET（0x06/0x07）、OVP（0x08/0x09）、OCP（0x0A/0x0B）、DELAY（0x0C/0x0D）或 REV（0x0E/0x0F）。 |
| 数字或曲线界面，光标 6（DATA 框） | 不写。 |
| 中文界面，光标 0 至 5 | 被选中列表值的 2 字节（光标 0 至 4），或关断时间的 1 字节（光标 5）。 |
| 中文界面，光标 6（列表选择） | 1 字节（0x3B）。进入中文界面也会强制做一次这样的保存（`0x0800E264`）。 |
| 工厂模式 | 工厂表，0x15 至 0x20。 |
| 设置菜单打开 | 不写；只重绘。 |

光标范围：在数字和曲线界面上旋钮把光标限制在 0 至 6；开机光标为 0（V-SET）（`0x0800E18A`）。光标 6 是 DATA（CRL）框：选中它时，帧不保存任何内容（`0x08001F8A`）。在中文界面上开机光标为 6。

磨损，推算：光标在 V-SET（默认）时，每帧都会重写 EEPROM 0x04 和 0x05 两个字节，占用 20 ms 主循环时间。查询也是帧。厂商上位机每 100 ms 轮询一次（VENDOR：上位机 V1.2）：约每秒 10 次写入，约 28 小时 100 万次写入。24Cxx 器件的额定擦写次数通常约 100 万次；实际器件及其额定值未知（速率为 INFERRED，代码路径为 FIRMWARE）。写入不会阻塞接收，但会使屏幕卡顿。

提示（由 FIRMWARE 推得）：长时间自动化测试之前，在面板上选中 DATA 框（光标 6），这样帧就不会写入任何内容。DATA 被选中时不要转动旋钮：那会清除 Ah、Wh 和时间统计（VENDOR 手册）。其结果是此后通过串口发送的内容都不会在断电后保存，这正是想要的效果。

通过串口发送的设置，只有当帧到达时其字段正好在光标下才会在断电后保留（默认是 VSET）；OPP、OTP 和 CC 优先只在退出面板设置菜单时保留；颜色总是保留；输出状态从不保留。

### EEPROM 映射

FIRMWARE（默认值 `0x0800D9F0` 至 `0x0800DE3E`，加载函数 `0x0800DE40`）。多字节设置为大端。

| 地址 | 内容 |

| 0x00 | 界面 |

## 10. 仅限面板的状态与设置菜单的影响

### 10.1 没有串口寄存器的状态

FIRMWARE（分发器在这些地方没有任何存储）：

- 界面（屏幕选择）、显示翻转、按键提示音、电流滤波；
- 电压和电流校准以及校正模式；
- 工厂模式；
- 统计：开机时间、电荷量、能量（在选中 DATA 框时转动旋钮清除）；
- 触发标志及其复位（按键）。

光标、界面和各项设置同样无法读回。

### 10.2 设置菜单

FIRMWARE。进入设备的设置菜单有以下影响：

- 输出被关闭一次（`0x08003AFE` 至 `0x08003B06`）；
- Vout、Iout、Pout 不再刷新，所以状态应答携带冻结的值（`0x0800C1CE`）；
- 调节 PWM 更新被跳过，PB13 脚（推断为输出放电脚，INFERRED）被强制拉低（`0x0800B2F4`）；
- 不检查 OPP 和 OTP（主循环只运行菜单例程）；
- 1 kHz 时隙中的 OVP 和 OCP 保持有效；
- 串口帧仍然被接受并应答。帧只会引起重绘，不写 EEPROM。
- 远程 ON（0x08）仍然会把输出使能脚驱动为开。在调节冻结且 OPP/OTP 未被检查的情况下这是个风险（代码为 FIRMWARE，效果为 INFERRED）。主机无法检测菜单是否打开（冻结的值看起来与稳定的值一样），所以在可能有人处于设置菜单时，不要通过串口开启输出。
- 退出时菜单保存 OPP、OTP、CC 优先和其他设置（`0x08004592` 至 `0x080045D4`）。

## 11. 主机的时序建议

除特别标注外均由上述代码路径推断（INFERRED）。

1. 每个 6 字节帧用一次写入发出。
2. 等待 ACK。它在帧尾上线后约 0.2 ms 内到达（经 USB 实测约 13 ms，MEASURED）。超时至少取 20 至 50 ms；本工具使用 300 ms。
3. 如果没有收到 ACK，至少空闲 11 ms 使解析器处于寻找帧头状态，然后清空输入并重发。
4. 查询之后，等待完整的 15 字节应答（最多约 55 ms；留出 100 ms）再发送任何内容。
5. 把应答视为最多 20 Hz；更快的轮询会被合并。数值以 10 Hz（Vout、Iout、Pout）或更慢的速度变化。
6. 校验每个应答（帧头、帧尾、校验和），并在下一个 `A5` 处重新同步。
7. 颜色帧之后，在最后一帧之后至少等待 300 ms；如有疑问，重发最后一个颜色。
8. 记录日志时慢速轮询（1 至 2 Hz）。每一帧都会产生一次 EEPROM 写入（第 9 节）。长时间的快速会话请使用 DATA 框提示。
9. 开启输出之后，等待约 1.5 s 的软启动，再相信 Vout 和字节 11。

- 0.05 A 时调节出的电流本身也有少许漂移（万用表波动 8.4 mA；第一次运行的窗口包含了阶跃瞬态，为 18 mA）。第一次运行没有 1.5 s 的稳定等待，设定误差相同（-0.5 至 +5.1 mA），但回读平均值被阶跃瞬态扭曲。
- 输出电压从 0.4 A 时的 3.04 V 升到 5 A 时的 3.49 V：负载在它自己的端子上保持 3.0 V，其余是万用表电流分流器和导线上的压降（合计约 0.1 Ohm）。
- 运行期间电源温度从 32.7 C 升到 36.0 C（5 A 时 17.5 W），输入为 65 W USB-PD 充电器（19.8 V）。

早先的 CC 点在约 3 V 输出、最大 1 A 下取得；新的点同样在约 3 V（按电源回读为 2.9 至 3.5 V）、最大 5 A 下取得。

### 12.5 开机时 CV 优先与 CC 优先

接入 3 V 恒压负载开机，ISET 0.5 A，20 Hz 采样：

| 优先级（寄存器 0x10） | 峰值电流 (A) | 峰值电压 (V) |
|---|---|---|
| CV 优先 | 0.811 | 4.263 |
| CC 优先 | 0.541 | 3.733 |

CC 优先限制了开机过冲。CV 优先时电流会瞬间超过 ISET 约 60 %；与 ISET 很接近的 OCP 此时可能触发（OCP 需要超限 100 ms）。回读值每 100 ms 刷新一次（第 5.5 节），所以真实峰值可能比这些读数更高。优先级已设回 CC 优先，即出厂默认值（串口设置的优先级断电后会丢失，除非之后退出了设置菜单，第 6.6 节）。

### 12.6 用电子负载测试 CC

不要用恒阻（CR）模式的负载测试限流。电源需要限流时，负载的 CR 环路与电源的 CC 环路互相对抗：电流每 0.5 至 2 s 在约 0 和 1.2 A 之间跳变（万用表同样看到），电源大部分时间处于 CV；工具读到的模式在 CV 和 CC 之间交替。即便如此，工具在 10 s 内记录的电荷量（0.00152 Ah）与万用表（0.00158 Ah）相差在 4 % 之内。请把负载设为低于 VSET 的恒压模式，或使用真实电阻来测试 CC。

### 12.7 其他观察

见过一次串口错误：WriteFile "access denied"（PermissionError 13），发生在第一次 OVP 触发和面板干预之后输出升到 3 V 时。重新打开端口后恢复正常，Windows 没有记录设备移除事件。本工具在串口 I/O 错误之后会重新打开端口并重试。

## 13. 本工具如何应用这些事实

| 事实 | 工具的做法 |
|---|---|
| 固件不检查任何范围（第 6 节）。 | 发送任何内容之前，每个值都先被换算并按面板范围检查。超出范围的值被拒绝。设定值四舍五入到 10 mV 和 10 mA，结果会说明实际发送了什么。OPP 必须是 10 W 的倍数（10 至 310），OTP 必须是 60、70、80、90 或 100 C。OVP 和 OCP 绝不低于面板最小值（0.50 V、0.10 A）。 |
| 未知 ID 会被应答，但仍会写 EEPROM；错误的值可能有危险。 | 除非给出 `--unsafe`，`raw` 拒绝未知 ID 和超范围数据，并让已有文档的寄存器走与其他命令相同的受保护路径。 |
| 与 VSET 相同或接近的 OVP 会因阶跃过冲而触发（第 7 节）。 | 工具要求 `OVP >= VSET + max(0.2 V, 1.5 %)`，对照给出的值和它上次发送的值检查。当 OCP 不比 ISET 高出 `max(0.05 A, 2 %)` 时会给出警告。 |
| OVP 和 OCP 在输出关闭时也与端子值比较。 | 低于端子当前读数（加余量）的新 OVP 或 OCP，在设定值发送之后、输出降下来之后才发送。如果输出开着且新值会使其触发（没有同时降低设定值），调用被拒绝。OPP 必须高于当前功率，OTP 必须高于当前温度（余量 5 W 和 5 C）。 |
| 帧的顺序很重要。 | 一次调用之内：OPP、OTP、CC 优先，然后是高于端子当前读数的 OVP 和 OCP，然后是 VSET、ISET、DELAY、REV 和关断电流。输出开启时同时降低 VSET 和 OVP，或同时降低 ISET 和 OCP，都不会触发（MEASURED）。 |
| 电源无法回报其设置。 | 工具记录它发送的每个值，并与状态一起显示（`last_sent`）。应当能在输出上看到的变化（输出开启时的 VSET、ON、OFF）会用回读来核对。 |
| 同时只有一个帧在途；交错风险；10 ms 解析超时。 | 一次一帧，收到最后一个字节后至少 3 ms 才发下一帧，超时 0.3 s，重试 2 次；应答缺失后等待 80 ms 并清空输入再重发。设置帧和查询是幂等的，所以重发是安全的。端口 I/O 错误会重新打开端口。 |
| 输出 ON 有软启动，且关闭时字节 11 无意义。 | `on` 会等待电压建立；只有字节 12 为 1 时才把 CC 标志当作模式读取。软启动按 1.6 s 留出时间。如果 DELAY 或 REV（按工具上次发送的值）超过 20 s，`on` 在发出帧后就返回，不再等待，除非给出了 `--wait-timeout`。`on` 把 Digital VSET 处或被选中列表的 VSET 处（均按上次发送的值）的 CV 读数视为已稳定；如果读数与两者都不符，则在软启动 1 s 后接受稳定的 CV 读数并说明这一点。 |
| Digital 寄存器在中文界面被忽略，而且驱动输出的列表无法读取。 | 输出开启时，没有效果的 VSET 在 3 s 后报告 NOT_APPLIED。输出开启时，如果列表选择的 OVP（按上次发送的值）不高于输出端当前电压加一个余量，会在发送前被拒绝。两者都已在中文界面上 MEASURED。 |
| 输出可以从面板开启。 | 当输出开启而工具并未开启它时，`status` 会给出提示。 |
| 帧会造成 EEPROM 写入。 | 等待期间，工具以 10 Hz 轮询（等待 DELAY 或 REV 时为 1 Hz）；每条命令打开并关闭端口，所以后台日志和前台命令可以共用电源。 |
| 颜色帧会启动约 210 ms 的保存，在保存期间到达的颜色帧可能没被保存。 | 工具在颜色帧之后等待 0.35 s，再重发最后一个颜色帧，使这次保存包含全部颜色。 |
| 工作台限值。 | 高于用户设定的工作台限值的电压类和电流类数值会被拒绝；如果实测电压超过电压限值 2 % + 50 mV 以上，`on`（未加 `--no-wait` 时）或列表选择会立即再次关闭输出。 |

## 14. 安全摘要

| 规则 | 原因 |
|---|---|
| 让 OVP 至少比 VSET 高 max(0.2 V, 1.5 %)。 | 阶跃过冲曾使 VSET 3.00 V 时的 OVP 3.00 V 触发。触发会一直响报警，直到按下面板按键。 |
| 绝不发送 OVP 或 OCP 为 0，或 OTP 为 0 至 5。 | OVP、OCP 或 OTP 为 0 是永久触发，即使输出关闭也一样；OTP 为 1 至 5 会在 10 至 50 C 时触发。 |
| 绝不发送数据为 5 或更大的 0x09，也绝不发送未知 ID。 | 该索引会被不加检查地保存，可能破坏 EEPROM。未知 ID 仍会触发 EEPROM 写入。 |
| 把每个值都限制在面板范围内。 | 固件接受并存储任何值。 |
| 不要长时间快速轮询。 | 每一帧都会写 EEPROM（光标在 V-SET、10 Hz 时约每秒 10 次写入）。 |
| 设置菜单打开时不要开启输出。 | 调节被冻结，OPP/OTP 不被检查。 |
| 把字节 12 降为 0 视为可能的触发或关断。 | 这是主机得到的唯一迹象，而且中文界面的关断是无声的。 |
| 设置了与 ISET 很接近的 OCP 时，保持 CC 优先（默认）。 | CV 优先时开机电流曾超过 ISET 约 60 %（MEASURED）；OCP 需要 100 ms，但很接近的 OCP 可能触发。 |
| 给容性或感性负载供电时，先接好负载再开启输出（厂商手册）。 | 向已经开启的输出接入这类负载会产生很大的冲击电流。 |
